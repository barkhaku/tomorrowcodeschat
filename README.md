# Chat Backend (Node.js + TypeScript + MySQL + Firestore)

* **MySQL 8**: `users`, `chats`, `chat_members` (source of truth for who is in which chat).
* **Firestore**: messages, read receipts, last-seen pointers.
* Strict TypeScript, zod request validation, membership checks on every chat operation.

## Setup
1. Install MySQL 8.0.16+ and create the database and user:
```sql
CREATE DATABASE chat CHARACTER SET utf8mb4;
CREATE USER 'chat'@'%' IDENTIFIED BY 'chat';
GRANT ALL PRIVILEGES ON chat.* TO 'chat'@'%';
```
2. Configure and run:
```bash
cp .env.example .env          # edit DATABASE_URL if your user/password differ
npm install
npm run dev                   # auto-runs the schema migration on boot
```
Firebase: put a service-account key at `./serviceAccountKey.json` (Firebase console -> Project settings ->
Service accounts), **or** run the emulator (`firebase emulators:start --only firestore --project demo-chat`) and set
`FIRESTORE_EMULATOR_HOST=localhost:8080` + `FIREBASE_PROJECT_ID=demo-chat` instead.

## Data model
**MySQL** – IDs are UUIDs (`CHAR(36)`) generated by the app. `chats.direct_key` is
`"<smallerUserId>:<largerUserId>"` with a UNIQUE key, so `createOrGet` is race-safe and
order-independent (A,B == B,A). All timestamps are stored in UTC.

**Firestore**
```
chats/{chatId}/messages/{messageId}                 senderId, text, createdAt (server timestamp), editedAt, deleted
chats/{chatId}/messages/{messageId}/reads/{userId}  userId, readAt
chats/{chatId}/lastSeen/{userId}                    userId, messageId, updatedAt
```
Design notes: timestamps are server-generated (clients can't skew ordering); read receipts are idempotent
(first read time kept); last-seen only moves forward; deletes are soft so receipts/pointers stay valid.
Ordering uses a single-field index on `createdAt` (auto-created by Firestore).

## API
Auth is out of scope: caller identity is passed as `userId`/`senderId` and checked against chat membership.

| # | Method & path | Body / query | Response |
|---|---|---|---|
| – | `POST /users` (helper) | `{ name }` | user |
| 1 | `POST /chat/create` | `{ userAId, userBId }` | `{ chatId }` (201 new / 200 existing) |
| 2 | `POST /chat/:chatId/message/send` | `{ senderId, text }` | message |
| 3 | `GET /chat/:chatId/messages?userId=&limit=50[&before=ISO]` | | `{ messages }` oldest→newest (latest N) |
| 4 | `POST /chat/:chatId/message/:messageId/read` | `{ userId }` | read receipt |
| 5 | `POST /chat/:chatId/lastseen` | `{ userId, messageId }` | last-seen |
| 6 | `GET /user/:userId/chats` | | `{ chats: [{ id, type, name, memberIds, createdAt }] }` |
| B | `POST /chat/group` | `{ creatorId, name, memberIds }` | chat |
| B | `POST /chat/:chatId/members` | `{ requesterId, userId }` (admin) | chat |
| B | `DELETE /chat/:chatId/members/:userId` | `{ requesterId }` (admin or self) | chat |
| B | `PATCH /chat/:chatId/message/:messageId` | `{ senderId, text }` | message |
| B | `DELETE /chat/:chatId/message/:messageId` | `{ senderId }` | 204 |

Errors: `400` validation, `403` not a member / not the sender, `404` not found, `500` unexpected.

## Quick try
```bash
A=$(curl -s -XPOST localhost:3000/users -H 'content-type: application/json' -d '{"name":"Alice"}' | jq -r .id)
B=$(curl -s -XPOST localhost:3000/users -H 'content-type: application/json' -d '{"name":"Bob"}'   | jq -r .id)
C=$(curl -s -XPOST localhost:3000/chat/create -H 'content-type: application/json' -d "{\"userAId\":\"$A\",\"userBId\":\"$B\"}" | jq -r .chatId)
M=$(curl -s -XPOST localhost:3000/chat/$C/message/send -H 'content-type: application/json' -d "{\"senderId\":\"$A\",\"text\":\"hi\"}" | jq -r .id)
curl -s -XPOST localhost:3000/chat/$C/message/$M/read -H 'content-type: application/json' -d "{\"userId\":\"$B\"}"
curl -s -XPOST localhost:3000/chat/$C/lastseen -H 'content-type: application/json' -d "{\"userId\":\"$B\",\"messageId\":\"$M\"}"
curl -s "localhost:3000/chat/$C/messages?userId=$A&limit=50"
curl -s localhost:3000/user/$A/chats
```
